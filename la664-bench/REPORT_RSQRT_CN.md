**平台精确指令 `xvfrsqrt.s`（默认，保留设计） vs 软件修正链（可选）：A/B 实测、守恒性与设计取舍**

- 日期：2026-09-28

## 0. 执行摘要

PeTar 的树力内核每个粒子对交互都要算一次 `1/sqrt(r²)`。上游 x86 与 ARM（Fugaku、TSV110）端口采用"硬件估计指令 + 多项式修正"的两段式；LA664 的情况特殊：它有一条**精确**的向量反比开方指令 `xvfrsqrt.s`（实测与 F32 `1/sqrtf` 逐位一致）。本报告用同一源码、同一选项构建 `hw`/`sw` 两个版本，从指令精度、指令吞吐、内核性能、端到端、N 扩展与守恒性六个层面做 A/B 对比，并给出最终设计取舍：**保留平台精确指令 `hw` 为默认实现**——它以零 rsqrt 误差改善了程序级力误差与守恒性，而在生产规模上性能与软件链等价（大算例甚至略快）；软件链 `sw` 保留为可选的构建分支。

| 维度 | `hw`（默认，保留） | `sw`（可选） | 取舍 |

**结论：**

1. **精度收益真实且可观测**：`xvfrsqrt.s` 的误差为零，使程序级力误差改善 16%（EP-EP）与 21%（EP-SP），并使守恒性在大算例上整体不变差、多数指标更好（N=16000 的末态能量误差约小一个数量级，角动量在 N=4000/16000 分别小 12%/24%）。
2. **生产性能代价极小**：N=2000 demo 端到端差 ≤0.5%（3 次极差内）；N=4000～16000 的弱扩展上 hw 反而快 0.3%～1.0%；只有"纯 rsqrt 密集"的内核微基准显示 hw 慢 1%～5%（单极内核 36%），这一劣势在真实算例中被 Amdahl 与访存等待稀释（§9.5）。
3. **因此保留 `hw` 为默认设计**：零误差的精确实现在科学上更可取，代价可忽略；`sw` 作为可选项保留（`make LARCH_RSQRT=sw`），适合需要与上游 x86/Fugaku 公式完全一致、或对密集微循环吞吐有特殊要求的场景。
4. **三架构对比表明这是 LA664 的微架构特性**：精确 rsqrt 的**延迟低但吞吐不足**（吞吐=延迟、不流水），而软件链借用双发射的普通 FP 流水线；在真实树遍历中两种效应相互抵消，精确指令的低延迟在短分组上反而占优。

## 1. 背景与问题

### 1.1 反比开方在 PeTar 中的位置

PeTar 树力（EP-EP、EP-SP）每次粒子对交互都要算

$$
r^{-1} = \frac{1}{\sqrt{r^2_{\text{cut}}}},\qquad
m_r = m_j r^{-1},\qquad
\mathbf{a}_i \mathrel{-}= m_r r^{-2}\,\mathbf{r}_{ij},\qquad
\phi_i \mathrel{-}= m_r .
$$

标量 F64 内核里这是一个 `fsqrt` + `fdiv`（实测依赖链 59 周期）；LASX 内核在 F32 下对 8 个通道同时计算，反比开方的实现方式直接决定内核的指令构成。

### 1.2 LA664 的指令现状

| 指令/入口 | 类型 | 实测 |
|---|---|---|
| 标量 `frecipe`（LSX 标量估计） | 估计 | GCC 头文件未提供（`__loongarch_frecipe` 未定义） |
| `xvfrsqrte.s` / `vfrsqrte.s` | 向量估计 | 存在但未使用 |
| `xvfrsqrt.s` / `vfrsqrt.s` | 向量精确 | **正确舍入**：2×10⁶ 随机输入与 F32 `1/sqrtf` 逐位一致 |
| `fsqrt` + `fdiv` | 标量精确 | 亦为精确 |

内核最初实现为软件修正链（与上游公式一致）。本轮 A/B 把两种实现放在同一源码、同一选项下逐项对比，并据此把**平台精确指令保留为默认实现**。

## 2. 两种实现与构建开关

### 2.1 精确指令（`hw`，默认）

`src/force_loongarch.hpp` 中：

```c
#if defined(LARCH_RSQRT_SW) && !defined(LARCH_RSQRT_HW)
static inline VF rsqrt_fast(const VF a) { return rsqrt_sw(a); }
#else
static inline VF rsqrt_fast(const VF a) {
#if defined(LARCH_SIMD_LSX)
    return (VF)__lsx_vfrsqrt_s(a);
#else
    return (VF)__lasx_xvfrsqrt_s(a);
#endif
}
#endif
```

单条指令得到正确舍入的 F32 结果（实测误差 0），依赖链延迟 25.0 周期/向量。

### 2.2 软件修正链（`sw`，可选）

`rsqrt_sw`：

$$
y_0 = \texttt{0x5f3759df} - (a \gg 1),\qquad
y_1 = y_0\,\frac{3 - a y_0^2}{2},
$$

$$
h = 1 - a y_1^2,\qquad
y_2 = y_1 + y_1\left(\tfrac12 h + \tfrac38 h^2\right).
$$

- 第 1 式：位魔数种子（5 位有效），2 条整数向量指令；
- 第 2 式：x86 端口 `RSQRT_NR_EPJ_X2` 的牛顿步（4 条 FP）；
- 第 3 式：Fugaku 端口的三次修正（5 条 FP）；
- 共 **11 条向量指令/向量**，8 通道 LASX 一次处理 8 个元素；最大相对误差 1.5e-7（满 F32 精度）。

### 2.3 构建开关与代码规模

`Makefile.in`：

```make
# Reciprocal-square-root implementation for the LoongArch kernels:
#   hw (default): platform vector rsqrt instruction (xvfrsqrt.s / vfrsqrt.s);
#                 correctly rounded and kept as the production design
#   sw          : bit-magic seed + Newton step + cubic correction
LARCH_RSQRT ?= hw
...
ifeq ($(LARCH_RSQRT),sw)
CXXFLAGS += -D LARCH_RSQRT_SW
endif
```

| 构建 | `petar` 大小 | `xvfrsqrt.s` 指令数（objdump） | `simd_test` 大小 |
|---|---:|---:|---:|
| `petar.rsqrt.sw` | 1 598 384 B | 0 | 74 344 B |
| `petar.rsqrt.hw` | 1 598 016 B | 4（内核 IV_J1/I1_JV 两处展开） | 74 296 B |

LSX 路径（`-mlsx -DLARCH_SIMD_LSX`，默认同样使用精确指令）编译通过；完整 LA664 程序在 LASX 与 LSX 构建下分别含 **4 条 `xvfrsqrt.s`** 与 **5 条 `vfrsqrt.s`**（按内核形状展开，单极/四极共用同一内联实现）。

## 3. 实验方法

| 层级 | 方法 | 规模 |
|---|---|---|
| 指令精度 | 2×10⁶ 随机输入比对 `1/sqrtf` | v ∈ [1e-6, 1e6] |
| 程序精度 | `petar.simd.test`（与 NoSimd 对比，阈值 7e-3） | Plummer N=1000×2000 |
| 内核精度 | `bench kernel check`（力/势 + 邻居计数逐粒子） | ni=500×nj=2000，两种形状 |
| 内核性能 | 内核扫描，单核绑核，预热 + 3 轮取最快 | ni∈{4,16,64,256,1024}，nj∈{8,32,128,512,2048}，4 内核 |
| 端到端 | N=2000 demo，t=1 Myr（512 树步） | 1×1 / 2×1 / 4×1 / 8×1(SMT) / 1×4(OMP)，sw/hw **逐次交替**各 3 次取中位数 |
| 单步分解 | 每步剖析的最大行（最慢 rank） | 3 次中位数，16 项 |
| N 扩展与守恒 | tamed IC，4×1，t=2 Myr，sw/hw 逐次交替 | N=4000 / 8000 / 16000，各 3 次 |

交替执行可消除机器漂移；内核基准由驱动内部对每次调用预热并取 3 轮最快值。

### 4.4 讨论

- 精确指令把 rsqrt 自身的误差从 1.5e-7 消除到 0；程序级力误差随之改善 16%（EP-EP）与 21%（EP-SP），说明软件链的 1.5e-7 在力误差中只占一小部分，主导项是 F32 累加与位置转换。
- 势误差与邻居计数不变（计数在两种构建下都与标量逐粒子一致），全部指标远优于 7e-3 验收阈值。
- 力误差的改善会在长时间积分中转化为守恒性的改善（§7.4）。

## 6. 指令吞吐与计算吞吐（RSQRT/cycle、RSQRT/s）

前面的内核与端到端测试回答了"两种实现在真实负载下谁更快"，本节从微架构角度量化两种实现本身的能力：**向量反比开方吞吐（RSQRT/cycle、RSQRT/s）**与**软件实现的"计算数吞吐"（指令数/周期）**，并与机器实测 FP 峰值（2 FMA/cycle、10 GFLOP/s）对照。这一节也解释了内核微基准差异的根因。

### 6.1 测量方法

- 使用**纯汇编内核**：每个循环迭代重复 N 份**完全独立**的运算（N=1/2/4/8），输入为常数，只测执行吞吐、不受依赖链延迟影响；
- 计时用 `perf stat -e cycles:u,instructions:u`，单核绑核；
- 指令计数与理论值逐一核对（例如软件链 8 份 = 8×11+2 = 90 条/迭代），确保没有被编译器/处理器删除；
- 对比对象：`mul`（8 通道乘法，作为 FP 发射峰值参照）、`hw`（`xvfrsqrt.s`）、`sw`（魔数+牛顿+三次修正，11 条指令/向量）、`sd`（`fsqrt`+`fdiv`），并把 `sd` 分解为 `sq`（`fsqrt`）与 `dv`（`fdiv`）。

| `sq`（`fsqrt`） | 18.51 | 0.0540 | 7.42 | 134.8 M | 2.31 |
| `dv`（`fdiv`） | 12.51 | 0.0800 | 5.02 | 199.7 M | 1.56 |

（单核、固定 2.50 GHz、8 份独立运算；`sd` ≈ `sq`+`dv`，说明两条指令走同一个串行单元。）

**三条立即结论：**

1. **硬件 rsqrt 指令的吞吐 = 它的延迟**：29.5 周期/向量，与依赖链实测的 25 周期同量级；1→8 份独立运算的每份成本几乎不变（29.55→29.51），完全不流水——这颗"精确 rsqrt"是一个**非流水化**的长延迟单元。
2. **软件链密集吞吐高 5.3 倍**：5.60 周期/向量（0.179 向量/周期、446 M 向量/s），且 1 份独立运算就已饱和；其瓶颈是发射宽度（90 条指令 / 44.8 周期 ≈ 2.01 条/周期），而非任何特殊单元。
3. **向量特殊单元普遍吞吐低下**：`fsqrt` 18.5 周期、`fdiv` 12.5 周期、`rsqrt` 29.5 周期（均为每 8 元素向量），三者串行相加恰好等于组合测试的时间；对照标量单元（标量 fdiv 5 周期、fsqrt 2 周期），LASX 的 sqrt/div 类指令不在普通 FP 流水线上，这正是"更专用的指令吞吐反而更低"的根因。

### 6.3 与机器 FP 峰值对照（计算数吞吐）

机器峰值数据：**FMA/mul 2 条/周期（0.200 ns/op，f64 10 GFLOP/s；8 链线性、4 线程 39.9 GFLOP/s）**，fadd 0.150 ns/op（2.67 条/周期），标量 fdiv 2.016 ns/op（5.0 周期）、标量 fsqrt 0.801 ns/op（2.0 周期）。

- **软件链的"计算数吞吐"**：每个 8 元素向量消耗 9 条 FP + 2 条整数指令，实测 5.60 周期 → 整体发射率 **2.01 条/周期**，其中 **FP 指令 1.61 条/周期（机器峰值 2 条/周期的 80%）**，折合 **FP 运算 4.02 G 条/s（峰值 5.0 G 条/s 的 80%）**；剩余 20% 是整数位操作与流水线气泡。软件链几乎把普通 FP 流水线"喂满"，而且可以与其它 FP 运算交错调度。
- **硬件指令的等效成本**：1 条 `xvfrsqrt.s` 占住机器 29.5 周期 = **≈59 条 FP 指令槽**（29.5 周期 × 2 条/周期）；软件链的 11 条指令只占 ≈11 个槽。以 FMA（0.200 ns/条、2 条/周期）折算机器时间：硬件 rsqrt ≈ 11.8 ns，软件链 ≈ 2.2 ns——**从"计算数吞吐"看，软件链便宜约 5.3 倍**。
- **与内核微基准完全吻合**：EP-EP 密集循环（nj≥128）hw 慢 5.1%、单极内核慢 35.9%（吞吐主导）；nj=8 时 hw 快 2.8%（短循环里指令条数主导：1 条 < 11 条）；EP-SP 四极每交互运算量大、rsqrt 占比低，所以两者持平（-0.3%）。
- **为什么它不转化为生产负载的劣势**：硬件 rsqrt 的**延迟**只有软件链的一半（25 vs 47 周期），真树遍历中大量分组是延迟敏感、且循环间存在访存等待，吞吐劣势被掩盖；同时 rsqrt 只占每次交互总运算的一小部分（§9.4/§9.5）。N=4000～16000 的实测证明生产规模上两种实现等价、hw 甚至略快。

### 6.4 小结

微基准层面，**LA664 的"精确 rsqrt"是低吞吐专用指令，29.5 周期/向量的成本约等于 59 条 FP 运算；软件链以 11 条指令（5.6 周期）达到同样的 1.5e-7 精度，密集吞吐高 5.3 倍**。这是软件链在内核微基准上领先的微架构根因；但精确指令的延迟优势与零误差精度，使它在真实算例中综合更优（§7、§9.5）。

## 9. 分析：延迟、吞吐与真实负载

### 9.1 延迟与吞吐的方向相反

| 实现 | 依赖链延迟 | 吞吐（8 份独立） | 每向量指令数 | 备注 |
|---|---:|---:|---:|---|
| 软件链 | 47.2 周期 | **5.60 周期/向量** | 11（2 整数 + 9 FP） | 普通 FP 流水线，可双发射、跨交互重叠 |
| `xvfrsqrt.s` | **25.0 周期** | 29.52 周期/向量 | 1 | 特殊功能单元，吞吐 = 延迟（不流水） |
| `fsqrt`+`fdiv` | 30.0 周期 | 31.02 周期/向量 | 2 | 同样是串行特殊单元（fsqrt 18.5 + fdiv 12.5） |

精确指令的**延迟**只有软件链的一半，**吞吐却只有软件链的 1/5.3**（§6）：软件链的 9 条 FP 指令可以在 2 条/周期的发射宽度里与其它运算交错执行，而每一条 `xvfrsqrt.s` 都独占一个不流水化的长延迟单元。内核实测（§5）与生产实测（§7）分别展示了这两种性质在不同负载下的表现：密集微循环由吞吐主导（sw 领先 ~5%），真实树遍历与短分组由延迟与访存行为主导（hw 不落后、大 N 略快）。

### 9.2 nj 交叉点

- **nj=8（短 j 循环）**：每次内核调用的固定开销（取数、广播、循环）占比高，rsqrt 的指令条数可被暴露 → hw 的"1 条指令、低延迟"占优（-2.8%）；
- **nj≥32（密集循环）**：流水线被喂满，吞吐成为主导 → sw 领先并稳定在 ~5%；
- 交叉点大约在 nj=16～32。

### 9.3 内核敏感度排序

| 内核 | ni=1024, nj=2048 的 hw/sw | 解释 |
|---|---:|---|
| EP-SP 单极 | **1.359** | 每交互总成本最低（1.09 ns），rsqrt 占比最高，吞吐差异完全暴露 |
| EP-EP | 1.051 | 树力主内核，其余运算较多但仍可见 |
| EP-SP 四极 | 0.997 | 每交互运算量大，rsqrt 完全被掩盖 |
| 邻居搜索 | 1.000 | 不含 rsqrt，天然无差异 |

### 9.4 Amdahl 放大器

树力只占单步的约 40%（1×1：11.0/27.2 ms）。即便树力内部整体差异 5%，端到端也只能被放大到 ~2%；实测单步 Total +0.4%（因为实际差异只发生在树力的 rsqrt 部分）。**在端到端层面，这个选择几乎不可见**；决定取舍的是精度与守恒性。

### 9.5 N 依赖：为什么大算例上两种实现几乎等价、hw 甚至略快

把弱扩展推到 N=16000（§7.3）后，出现了一个值得解释的现象：**内核微基准里软件链在大 nj 密集中快 5%，但真实算例在 N≥4000 时两种实现差异 ≤1%、hw 甚至略快**。三个因素共同解释：

1. **Amdahl 稀释**：内核里 5% 的差异对应到单步只有树力的一部分；N=16000 时树力占单步约 69%（95.1/137.3 ms），此时 1% 的单步差已接近可观测上限，符合实测。
2. **真实树的多相混合**：内核微基准是"纯 rsqrt 密集循环"，而真实树遍历中大量时间在访存等待与分组调度；在 nj 较小、延迟敏感的分组上，`xvfrsqrt.s` 的 25 周期低延迟反而占优（内核 nj=8 时 hw 快 2.8%，§5.4）。两种效应在整棵树里相互抵消。
3. **随机性下限**：大 N 下不同构型的硬双星事件历程不同（N 体混沌），PP 集群/建组等同量级部件本身有 ±4% 的 run 间波动（§7.3 表），墙钟的 ≤1% 差异在统计噪声内。

因此可以给出生产层面的结论：**N=4000～16000 时两种实现性能等价（hw 略优）；结合守恒性上 hw 的系统性优势（§7.4），保留 hw 为默认设计是综合最优的选择**。

## 10. 三架构实现对比

### 10.1 x86（AVX2 / AVX512）

估计指令 `_mm256_rsqrt_ps`（AVX512 为 `_mm512_rsqrt14_ps`），最大相对误差 ≤ 1.5×2⁻¹² ≈ 3.7e-4；随后修正。`src/phantomquad_for_p3t_x86.hpp` AVX2 EP-EP 核心：

```c
v8sf ri1 = _mm256_rsqrt_ps(r2);          // 12 位硬件估计
v8sf ri2 = _mm256_mul_ps(ri1, ri1);
#ifdef RSQRT_NR_EPJ_X4                    // 64-bit 模式：更高阶多项式 + 牛顿
    ...
#elif defined(RSQRT_NR_EPJ_X2)            // 默认：一次牛顿步
    ri2 = _mm256_fnmadd_ps(r2, ri2, _mm256_set1_ps(3.0f));
    ri2 = _mm256_mul_ps(ri2, _mm256_set1_ps(0.5f));
    ri1 = _mm256_mul_ps(ri2, ri1);
#endif
```

默认 `RSQRT_NR_EPJ_X2`（`src/petar.hpp` 中按精度模式定义）：估计误差 3.7e-4 经牛顿平方收敛 → ~1.4e-7，满足 F32。F64 路径通过 `cvtpd2ps → rsqrt → cvtps2pd` 复用 F32 估计。

### 10.2 FACortex-A64FX（FUGAKU）

`src/force_fugaku.hpp`（SVE）：

```c
svfloat32_t rinv = svrsqrte_f32(op);              // ARM FRSQRTE 估计（~2^-8）
svfloat32_t h = svmul_f32_z(pg, op, rinv);
h = svmsb_n_f32_z(pg, h, rinv, 1.f);              // h = 1 - x*r^2
svfloat32_t poly = svmad_n_f32_z(pg, h, svdup_f32(0.375f), 0.5f);
poly = svmul_f32_z(pg, poly, h);
rinv = svmad_f32_z(pg, rinv, poly, rinv);          // r += r*h*(0.5+0.375h)
```

估计精度低（2⁻⁸ ≈ 3.9e-3），但三次修正（5 条 FP 指令）即可把误差压到 ~1.6e-7。该公式后来被 LA664 与 TSV110 端口直接沿用。

### 10.3 Kunpeng-920（TSV110，NEON）

`src/force_tsv110.hpp` 与 FUGAKU 同构，只是 4 通道：

```c
static inline float32x4_t rsqrt4(float32x4_t x){
    float32x4_t r = vrsqrteq_f32(x);               // ARM FRSQRTE 估计
    float32x4_t h = vmulq_f32(x, r);
    h = vfmsq_f32(vdupq_n_f32(1.0f), h, r);
    float32x4_t p = vfmaq_n_f32(vdupq_n_f32(0.5f), h, 0.375f);
    p = vmulq_f32(p, h);
    return vfmaq_f32(r, r, p);
}
```

实测：估计 3.28e-3 → 三次修正后 1.66e-7；一次/两次牛顿分别为 1.61e-5 / 1.44e-7。四极内核曾对比"三次修正 + 半步牛顿"（`NEON_QUAD_NEWTON`），结论是**精度无提升、慢约 20%**，默认关闭——与本报告"额外修正不等于更快"的结论相互印证。

### 10.4 LA664（本报告）

| | 默认（`hw`） | 可选（`sw`） |
|---|---|---|
| 入口 | `xvfrsqrt.s`（精确） | 位魔数种子（不用估计指令） |
| 修正 | 无 | x86 牛顿步 + Fugaku 三次修正（11 条指令） |
| 精度 | 0（正确舍入） | 1.5e-7 |
| 实测 | 生产规模等价或略快；守恒性更好；仅密集微循环慢 1%～5% | 微循环吞吐高 5.3×；nj=8 短循环慢 2.8% |
| 定位 | **默认，保留设计** | 可选构建分支 |

| 硬件估计 | `rsqrt_ps` / `rsqrt14_ps`，~3.7e-4 | `FRSQRTE`，~2⁻⁸ | `FRSQRTE`，实测 3.28e-3 | 有 `xvfrsqrte.s`，**未用** |
| 精确指令 | 无 | 无 | 无 | **有 `xvfrsqrt.s`（误差 0）** |
| 采用的方案 | 1 次牛顿（X2）；64-bit 更高阶（X4） | Fugaku 三次修正 | 同 Fugaku；四极可选半步牛顿（弃用） | **精确指令（默认）**；软件链（可选） |
| 最终精度 | ~1.4e-7 | ~1.6e-7 | ~1.7e-7 | **0（hw）/ 1.5e-7（sw）** |
| 入口吞吐（实测） | 估计指令（典型 1–2 周期级） | 同左 | 同左 | **hw 29.5 周期/向量（0.034 vec/cycle、84.5 M/s）；sw 5.60 周期/向量（0.179 vec/cycle、446 M/s）** |
| 性能取向 | 估计快，修正划算 | 估计 + 三次修正即达极限 | 修正足够，更多修正无益 | 精确指令保精度；软件链保密集吞吐 |
| 关键差异 | 依赖硬件估计质量 | 公式成为模板 | 128 位极简 | 唯一拥有精确向量 rsqrt；按"精度优先、生产等价"保留精确指令 |

### 10.6 讨论

1. **估计指令的可用性决定路线**：x86/ARM 只有廉价近似估计，必须"估计 + 修正"；LA664 的标量估计不可用，端口保留了一条位魔数软件链作为备选，但最终默认采用平台唯一的精确向量指令，精度（0）不依赖任何近似或多项式。
2. **精确 ≠ 密集循环更快，但生产等价且守恒更好**：LA664 的 `xvfrsqrt.s` 延迟最低（25 周期），但吞吐只有 0.034 向量/周期（29.5 周期/向量，非流水化），等价于 59 条 FP 指令的发射资源；软件链 0.179 向量/周期（5.60 周期/向量）高 5.3 倍。在"每个 j 迭代调用一次"的密集微基准里软件链更快，但在生产规模的完整算例中差异消失（§9.5），而精确指令以零误差换来更优的守恒性——这正是保留它的理由。
3. **与 TSV110 结论一致**：额外修正步（半步牛顿）和精确指令都不自动带来微基准收益；**吞吐、延迟与真实负载的匹配才是设计依据**。

---

## 11. 结论与建议

1. **默认保留 `hw`（平台精确指令）**：精度 0（正确舍入），程序级力误差改善 16%～21%；生产规模性能与软件链等价、大 N 略快 0.3%～1.0%；守恒性在能量（N=16000 约 15 倍）与角动量（N=4000/16000 小 12%/24%）上更优。这正是"仅损失极少性能、换取可观测守恒性提升"的取舍。
2. **`sw`（软件链）作为可选分支保留**：`make LARCH_RSQRT=sw`；适合需要与上游 x86/Fugaku 公式完全一致的对照构建，或在 nj≤8 之外仍有极端密集 rsqrt 微循环的场景（其密集吞吐高 5.3 倍）。N=4000～16000 的大算例上两者性能等价（≤1%），可按公式一致性或吞吐偏好取舍。
3. **对 LA664 移植的启示**：平台数学指令（精确 rsqrt）的延迟优势与零误差精度可以兑现为守恒性收益；其吞吐短板只出现在极端密集的微基准中，真实负载下不构成劣势。LASX 的 sqrt/div 类指令不在普通 FP 流水线上（fsqrt 18.5、fdiv 12.5、rsqrt 29.5 周期/向量），软件实现仍是对照与兜底方案。
4. **后续优化方向不变**：树力已非最大热点，短程 PP 力与集群搜索才是下一块杠杆；反比开方这条线已经探明，无需继续投入。
